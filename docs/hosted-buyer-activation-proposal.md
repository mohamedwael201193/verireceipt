## Hard blocker before genuine activation

The reviewed service can accept many public plan IDs up to its shared daily cap.
Cookie/session protection is not operator authorization. A one-call grant cannot
safely turn that service on unchanged, even briefly. A hidden URL or intent to
switch it off quickly is not a spending control.

Before loading a genuine key, add and independently review an operator arming
latch: disabled by default, durable across restart, restricted to one approved
payer + plan ID/hash, UTC expiry and exact 10,000-micro test-USDC lifetime ceiling.
Consume the latch atomically with reservation before execution. Unknown outcomes,
server restart, duplicate requests and a new plan must never re-arm it. The latch
must reject alternate owners/plans and concurrent starts. It must not alter the
frozen policy, published preview charge or v1 records. This is a separate offline
code increment and does not exist in the reviewed revision yet.

Additionally restrict all buyer endpoints at both frontend proxy and directly
reachable backend to the authorized operator during the test. Validate that a
second clean browser and direct-backend request cannot create or buy a plan.
Ingress gating is defense in depth, not a substitute for the durable one-shot
latch. Do not enable the buyer until both are demonstrated.

## Rollback and stop rules

Before signing: disarm/disable and verify new reservations are refused. Retain
any reservation already written. After signing or an unknown response, disabling
is a forward stop only, not revocation, refund or cancellation. Do not delete the
SQLite authority, reset the latch, release uncertain exposure manually or reuse
the payer elsewhere. Keep the running job's bounded closeout and read-only
reconciliation possible. Never restore an old database snapshot to regain budget.

Rollback app revisions only after the buyer is off and all active work is closed
or conservatively classified. Retain the same database with compatible code;
do not start a second authority. Remove the host key reference once no approved
signing work remains, without printing it. Key removal cannot undo signatures
already produced. Funding recovery/withdrawal is a separate operator-approved
wallet operation, not an automatic rollback.

Download private evidence within 24 hours of reservation if it is to be retained
for review, and confirm that private retention destination before copying it.
Application cleanup runs on startup/hourly, payload access ends at 24 hours,
minimal accounting/idempotency tombstones at 48 hours. This is not forensic
storage/backups erasure. Report the final disabled state and unresolved exposure
to Mo. Preserve a private read-only reconciliation route while retention remains
active, even if the paid routes are disabled. Do not call the demonstration complete just because a process started.
