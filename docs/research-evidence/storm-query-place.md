# Storm query place selection, November 25, 2026

Only an absent declared location enables query prose extraction. An inline decimal coordinate pair is passed through the existing bounds validator without geocoding. Otherwise candidates are tried in order: place after a supported preposition, filler-stripped text, original text. Temporal suffixes and sentence punctuation end extraction, while an internal administrative comma is retained. Duplicate candidates are removed. First ranked geocoder hit wins, retaining the existing provider-order/not-confirmed-unique selection disclosure and raw chosen response in the receipt. Explicit location input is never rewritten. All empty candidates remain PLACE_NOT_FOUND 422; transport failure or malformed top result remains a source error, never a guessed location.

Fresh public Open-Meteo Miami captures and matching NWS Miami points/active-alert response bytes have exact URL/status/time/SHA256 provenance. The new handler controls replay those bytes and deliberately fail the optional forecast source, so no retimed or invented forecast is used. Empty geocoder envelopes and malformed top-result bodies are negative controls, not invented place evidence. A handler run may now make up to three sequential geocoder requests when earlier candidates return empty, sharing one six-second deadline. Abort-ignoring fetch and body promises are bounded with a race, and no later candidate starts after expiry. No polling, source change, manifest, shaping or risk-formula change.

271 tests across seven affected suites pass; source typecheck and diffcheck pass. Eleven isolated mutants turn assertion RED for extraction call site, extracted candidate, stripped/original fallback, inline coordinates, declared-input precedence, first-hit stop, temporal/filler stripping and punctuation. This is source review material, not a live deployment or score-improvement claim.
