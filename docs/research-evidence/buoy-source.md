# Hourly-cached Boston buoy source factory

Unwired implementation only. No route, default approval, YAML declaration or registration. Uses the reviewed Boston buoy parser and exact fixed NOAA table/metadata URLs. Caller supplies reviewed terms configuration. Tests use synthetic risk acceptance, not production approval.

One station-pair attempt per hour per source instance, including failed/malformed/MM/stale outcomes. Both temperature metrics share the same raw table and metadata, coalesced during concurrent reads. No cache per metric or per caller, no background polling and no rapid outage retry. On expiry, exactly one new pair attempt; old data is not stale-while-revalidated. Source fetch timestamps and original observation time remain unchanged on hits. Parser rechecks90minute observation age every time; stale/MM refuses without refetch until the hourly boundary and without older-row substitution.

Scope of rate guarantee: in-memory, per process and source instance, resets on process restart. Production route must instantiate once and deployment must remain one process or add shared cache/budget before scaling. This module does not promise a fleet-wide or restart-proof hourly cap. Upstream guidance asks minimal retrieval, most stations hourly. Source: https://www.ndbc.noaa.gov/faq/rt_data_access.shtml . No repeated live reads were started for this slice; tests replay the retained real table/metadata.

Two fixed public HTTPS reads in parallel,2s full-read bounds,1MB table/250KiB metadata, strict UTF8 reader, redirects rejected. Existing shared bounded reader used unchanged. Outer observation runner2.5s prevents late receipt even if a transport ignores abort. Source reads may finish within their own2s after an individual caller aborts so shared concurrent readers are not poisoned; an aborted caller never receives a receipt. Failed load consumes the hour, no immediate new attempt.

Receipt preserves exact original table/metadata strings, metadata URL/fetch time, table fetch time, original UTC observation time, value/units/station/QC/scope and truthful terms booleans. Shared receipt runner handles hashing and once-only persistence. Not independent physical sensor authentication; metadata association cannot prove arbitrary table authorship. Automated gross-error QC, not final post-processing, subject to revision. No general sensor or datacenter coverage.
