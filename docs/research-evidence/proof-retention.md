# Proof evidence retention

PROOF_RECEIPT_IDS is a deployment-only comma-separated list of complete rcpt_ ids (26 uppercase alphanumeric characters after the prefix), maximum64unique ids. Whitespace and repeats are harmless. Invalid configuration refuses pruning instead of risking a proof. Keep this env setting across deploys and restarts; it is not set by a public request and the list is extendable without code changes. No receipt ids are inferred from abbreviated citations. Pinning never recreates already-pruned evidence.

Both storage backends exclude configured proof main and page bytes from the ordinary pruning total and victim selection. The fresh write remains exempt from its own prune. Receipt metadata and original hashes remain immutable. A single oversized receipt still follows the existing no-blob policy; pinning is for a few normal-sized proofs, not unlimited storage.

EVIDENCE_BUDGET_MIB is an integer1through500; absent or empty defaults to300MiB. Change only after checking disk usage. The default increase was selected against measured database usage203.4MB of1020.7MB, not a plan upgrade. Pinned bytes and database overhead are additional to this budget. Each completed prune logs ordinary bytes and cap, with a warning at80percent. No identifiers or evidence are logged.
