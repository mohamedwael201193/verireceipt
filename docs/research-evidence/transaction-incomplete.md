# Incomplete transaction input, November 25, 2026

Hex-shaped non-hashes no longer become INVALID_TX_HASH or a narrative scenario assessment. A 40-hex input (optional prefix/case normalized) runs exact address screening against the existing official OFAC SDN CSV source only. The answer states match or non-match and explicitly limits the result to list membership, not transaction risk or safety. Other incomplete/hash-shaped input gets a local explanation that no full 64-hex transaction hash was provided and no chain lookup can run. Both return null risk_level/risk_score, unverified verdict and confidence 0. No transaction grade is invented even when a listed address matches. Full hashes retain the existing RPC quorum/rubric and scenario prose retains its existing disclosed assessment.

Address evidence includes exact raw list bytes, address count, match result and SHA256 receipt. Source failure/empty extracted corpus refuses rather than reporting a non-match. Incomplete input also requires successful receipt storage. Raw length/control validation happens before trimming, including DEL. Missing input remains MISSING_PARAM. The diagnostic HTTP tests now expect 200 without an error/input-shape record for incomplete inputs; no input fragment is logged and logging code is unchanged.

New positive/negative address controls reuse the existing unmodified real full OFAC capture in tests/fixtures/fraud/sdn.csv, documented in fraud-detection.md (official source captured November 23, 2026, 5,855,269 bytes, 94 unique extracted addresses (the earlier source report counted 100 raw occurrences)). The negative address comes from the existing actual transfer transaction fixture and is asserted absent from that corpus. No fabricated sanctions entry or new raw corpus is introduced. Existing older synthetic-labelled rubric tests remain unchanged beyond the incomplete-input expectation. Negative source bodies and malformed strings are refusal controls, not source claims.

294 tests across twelve affected suites pass. Source typecheck and diffcheck pass. Eleven isolated assertion mutants turn RED for invented level/score/confidence, always-positive/negative/skipped screening, false screening claim, empty corpus acceptance, scenario misrouting, trim-before-control validation, and missing hash limitation. No manifest, registration, RPC or transaction side effect. Source publication and deployment require their separate gates.
