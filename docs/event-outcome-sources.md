# Event outcome sources

Source order is exact or uniquely contained binary prediction-market resolution, then the existing exact-title encyclopedia election resolver, then a structured event winner resolver. A matched market is never replaced by another source. Open markets keep their existing unresolved response; ambiguity, nonbinary outcomes, pending settlement and unclean resolution keep their existing errors.

The structured resolver accepts only a dated or Roman-numeral who-won event phrase, at most120characters. It requires one exact normalized English label, one nondeprecated winner, and a past event date or end date. A start date alone is not completion. The winner is the linked item's English label, never inferred from the question or event title. The English encyclopedia page is a reference link only, not corroboration. The answer always discloses single structured-data source (Wikidata), not independently corroborated. This is a record lookup, not independent adjudication.

Only genuine EVENT_NOT_FOUND misses across all resolvers produce a no-source unresolved response: resolved_yes is false, no winner, no receipt and sources is empty. This does not mean NO. Matched structured ambiguity, missing winner/English label, incomplete or future dates and multiple winners keep distinct refusal codes, never a no-record claim. Upstream HTTP, timeout, malformed payload and receipt-storage errors never become this response.

Event requests have a2900ms response ceiling, a2700ms source-work budget and650ms per-read ceiling. URL-identical reads share ownership until the underlying fetch and body settle, even if callers time out. Concurrent source reads are capped at32. No new request starts after its budget expires. Timing out does not assert an event result.
