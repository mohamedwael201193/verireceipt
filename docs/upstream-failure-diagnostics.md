# Holder and metric refusal source diagnostics

Failed holder indexer lookups retain their existing INDEXER_UNREACHABLE response and message. Process-local WeakMap metadata records blockscout or geckoterminal plus upstream_failure: rate_limited for observed HTTP429 or existing429cooldown, unreachable for fetch/body-read/HTTP failures, bad_payload for parse/identity/count/source-time validation failures, unknown when no instrumented boundary establishes a class. Local queue/capacity errors remain unknown, not invented network failures. Existing cooldown does not cause an additional network call.

Metric final quorum refusals log the failing configured operator when unique, mixed when several operators failed, unknown when none failed or the static operator mapping is absent. Failure classes summarize instrumented failures: rate_limited, unreachable, bad_payload, other, unknown, mixed. Wrong chain and not-finalized retain the existing provider_failure classification and use other in the new coarse field. Timeouts are unreachable; uninstrumented semantic field failures and local source-capacity errors remain unknown. Independent variation in operator and failure class produces mixed independently; this does not attribute every class to every named operator. Quorum disagreement among fully completed legs has unknown/unknown, not a claimed transport fault. Existing diagnostic fields are retained.

Only closed enums are accepted. No input, token, address, URL, arbitrary upstream name, error message or response body is logged by this change. Metadata never enters JSON errors, answers or stored evidence. Existing successful receipt evidence, stale-cache behavior, source starts, ownership, deadlines, retries, queue, cooldown and verdicts are unchanged. This patch does not add coalescing or bypass HTTP429. Diagnostic operations are synchronous side-table writes and closed labels, not additional awaits or timers.

Contracts rechecked: https://devnode.telegraphprotocol.com/engine/v1/intents/TOKEN_HOLDER_COUNT_GENERAL and https://devnode.telegraphprotocol.com/engine/v1/intents/ONCHAIN_METRIC_VERIFY_GENERAL . No answer contract is changed. No claim is made that these classes explain previous scores or that a historical burst used identical questions.
